一、 简介

自然语言处理引擎用于自动分析理解非规则化的语音数据。引擎提供以下 API 接口：
         • 知识库管理
         • 人机交互记录管理
         • 训练数据管理及引擎训练
         • 语音意图识别
          • 静默坐席开发框架
          • 备份管理
          • 配置管理

以下约定适用于本文档：
     • NLP Engine 通过 Cloud 方式提供给 Application Developer（应用开发者）进行应用开发。
     • 所有URL前面应加http://<Server_Address>:<Server_Port#>，其中Server_Address和
           Server_Port#分配给Application Developer独立使用。如被分配https接口, 即在URL前应
           加https://<Server_Address>:<Server_Port#>。
            如：/faq/search/all，如果被分配的Server_Address为nlp.ts.com，Port#为 12345，则该URL
                的完整应为：http:// nlp.ts.com:12345/faq/search/all。如被分配https接口, 则该URL的应
                为: https:// nlp.ts.com:12345/faq/search/all。
     • 如使用 NLP Engine 提供的 Web UI，浏览器建议使用 Google Chrome。
     • 请注意本系统所有操作编号为 UTF8, 并不接受 BIG5 或 GB 码。还有在编辑下面的 CSV 的例子中, 请
           用 Notepad++编辑, 然后选择 UTF8 保存。 如用 windows 内置的 notepad 选择 UTF8 保存,
           windows 可能在 csv 中增加一些隐藏符号, 从而引起导入问题。

三、 知识库管理

ENGINE 的知识库为树状结构，由分类和知识点组成。分类将知识点分门别类，使得知识库易于管理。建立
知识库时，分类有多重类型可以选择，以用于处理不同的知识结构。引擎主要有以下六种分类模式：

分类类型                         主要用途

标准 (Standard)                用于一般自然语言文本处理, 主要和其他分类不同之处是当引擎在 ROOT 分类

                             被查询时(单元六接口), 引擎会搜寻「标准分类」及「细化型分类」中的知识

                             点。 如果在那个分类(question_id)下搜寻, 则只会搜寻该分类及其所有子分

                             类中的知识点。 但如果答案在「标准」分类中, 系统是不会有(followUp)跟进

                             回复。 详细关于(followUp)跟进回复, 会在本文件「高阶引擎功能」单元再详

                             细解释。

                             基本上除非有特定用途, 分类类型一般只需要选择「标准」即可。 一个「标准

                             型分类」下, 无论开了多少个「标准型子分类」, 引擎被查询时会将所有「标

                             准型分类」的知识点(意图)统一处理, 母或子分类都不会有什么区别。

枚举(Enum)                     主要是用于「顺序型问卷分类」, 一般引擎在被查询时一般不会访问「枚举分

                             类」下的知识点(意图), 除非被主动指示在该类型下寻找。 详细「枚举分类」

                             如何应用在「顺序型问卷」会在本文件「高阶引擎功能」单元中说明。

树状型问卷                        这是引擎中的高阶功能, 适用于做「树状型」形式的问卷调查的「上下文功

(Questionnaire_Branching) 能 」, 简单例子如下:

                             ------

                             【范例: 甲公司服务调查问卷】

                             问题一:
                             你满意我司服务吗?
                             1. 满意(跳往问题二)
                             2. 不满意(跳往问题三)

                             问题二:
                             你满意什么服务呢?
                             1. 售前服务(跳往问题四)
                             2. 售后服务(跳往问题五)
                             3. 其他 (跳往问题六)

                             问题三
                             你不满意原因是什么呢?
                             1. 职员态度(跳往问题七)
                             2. 产品价格(跳往问题八)

                                         3. 其他(跳往问题九)

       -------

       引擎被查询时访问到「树状型问卷分类」时, 系统会在回复时加上”followUp”
       在回复内, 用意是指示查询者答案会可能在那个「树状型问卷子分类」中, 让
       查询者利用这个子分类继续搜索, 直至得出最终答案。

       还有一点和「标准型分类」不同之处, 是「母分类」和子分类中的知识点(意
       图)是有层次的概念, 「标准型分类」是没有的。 当查询「树状型问卷分类」
       时, 引擎只会寻找这个「树状型问卷分类」下一层的知识点, 其他同层分类或
       上层分类的知识点, 是不会被包括在搜寻的范围内, 「标准型分类」中的知识
       点被搜寻时, 不理上层下层, 都会一起包括在搜寻范围内。

       详细关于「树状型问卷」会在本文件「高阶引擎功能」单元再详细解释。

顺序型问卷  这是引擎中的高阶功能, 适用于做「顺序型」形式的问卷调查的「上下文功

(Questionnaire_Stepping) 能 」, 简单例子如下:

       -----
       【范例: 购买机票系统】

       问题一： 起飞地点是什么?

       问题二： 降落地点是什么?

       问题三： 起飞日期?

       问题四： 客舱等级?
       ------

       和「树状型问卷」不同之处, 无论使用者如何回答, 问题都会顺序问下去, 不会
       因为回答跳到其他分类的知识点之中, 引擎回复的 followUp 也一定只会是下
       一层的分类, 详情如何操作会在本文中的「高阶引擎功能」说明。

       还有一点要注意是「顺序型问卷分类」可和「枚举型分类」。 就如上面的范
       例, 起飞地点和降落地点, 其实回复都是城市, 开发者可创造一个关于城市的
       「枚举型分类」, 然后链接上的「顺序型问卷分类」中, 以减少开发者重复制

使用 websocket, URL 入口有两种, 一种是 ws, 另一种是加密通道 wss。 譬如使用/api/uaudio/websocket
接口, 则 URL 在 ws 情况下是:

     • 所有URL前面应加ws://<Server_Address>:<Server_Port#>，其中Server_Address和Server_Port#

           加wss://<Server_Address>:<Server_Port#>。

如：/api/uaudio/websocket，如果被分配的Server_Address为nlp.ts.com，Port#为 12345，则该URL的
完整应为：ws:// nlp.ts.com:12345/api/uaudio/websocket。如被分配加密通道接口, 则该URL的应

AUTH_TYPE,ANT_URL,ROLE
BASIC,/api/response/clear,ADMIN
BASIC,/api/faq/clear,ADMIN

BASIC,/api/faq/all,LOGIN
BASIC,/category/all,LOGIN
WEB,/Faq.html,LOGIN
WEB,/,LOGIN
WEB,/report.jsp,LOGIN

9.2 分类跳转（Category Switching）

针对上下文对话，引擎提供分类跳转功能。当引擎识别到用户问题的意图时，引擎可以将当前对话跳转到指
定的对话流程，用户的下一次提问就可以进入到指定的对话流程。结合训练数据，引擎可以做到对话流程的
灵活跳转。

分类跳转功能使用的场景是当用户在某一分类下提问与此分类不相干的问题时，开发者在该分类下添加一条
知识点用于匹配该类问题，然后将该知识点指向需要的目标分类。具体配置方法如下：

例如 ROOT 分类下有 A、B、C 三个标准型分类。分类 A 下有 3 个 FAQ，分类 B 下有 2 个 FAQ，分类 C 下
有 2 个 FAQ，Faqid 依次为 1 至 7。假设引擎将用户的问题识别为 FAQ 2 时，引擎跳转到分类 B 中，下次
用户的问题跳转分类 B 中进行匹配；同理引擎识别到 FAQ 3 时，将跳转到分类 C。

分类跳转功能需要在 Category Switching 栏里用 JSON 格式指明 Faqid 和目标分类的 QID，格式如下：

{"<Faqid_1>":"<QID_1>","<Faqid_2>":"<QID_2>"}

其中，Faqid 为当引擎匹配到哪一条 FAQ，分类才需要跳转；QID 为需要跳转的目标分类的分类路径，各分
类之间用“->”间隔。

附录四: 语音转文字功能说明

除了语音意图识别功能之外，引擎还提供语音转文字功能，该功能可以将输入的语音转换成预设语种的文
字，目前仅支持中文和英文。请注意，语音转文字功能非标准功能，需在指定版本引擎中开启才可使用。并
且该功能与语音意图识别功能不可以同时使用，当语音转文字功能开启时，语音意图识别功能自动失效。

以下为语音转文字功能的介绍和使用方法：

1. 上传语音文件进行语音转文字

HTTP    Post
Method

功能      上传特定格式的语音文件到引擎，引擎会将该语音文件的内容转换成文字。

输入      File (form-data name=”data”)

        文件类型：WAV 文件，语音格式为 signed 16 bit pcm(raw) mono 格式

输出      数据类型：纯文本

        以纯文本形式输出转换后的文字。

引擎提供通过传送语音流的方式进行语音转文字，分为单次转换和连续转换，两种转换方式都是基于
